Рендер кликов макроса — документация
Инструмент берёт файл макроса Geometry Dash (список кадров с нажатиями) и превращает его в аудиофайл с кликами — тот же результат, который даёт рендер кликбота, только прямо в браузере, без установки ZCB.
Всё вычисляется локально на вашем устройстве. Файлы макроса и звуков никуда не отправляются.
1. Загрузка макроса
Поддерживаемые форматы (определяются автоматически по содержимому файла, не по расширению):
Формат
Расширение
Как устроен
GDReplayFormat 2
.gdr2
Бинарный формат. Файл начинается с байтов GDR, дальше — метаданные (fps, автор, длина) и упакованные события кликов по каждому игроку.
GDReplayFormat 1
.gdr
Данные закодированы в MessagePack (бинарный аналог JSON).
Универсальный JSON
.json
Массив кадров с полями вида frame/p1/p2, либо frame/player/down, либо объект-карта { "123": {...} }.
Если файл — GDR2, программа сама прочитает fps записи из самого файла и подставит его в настройки. Для JSON и GDR1 fps нужно проверить вручную (поле «FPS уровня» появляется после загрузки) — если клики на таймлайне выглядят растянутыми или сжатыми относительно ожидаемой длины уровня, поправьте fps или единицы времени (кадры / мс / секунды) и нажмите «Пересчитать».
После разбора появляется таймлайн — две дорожки:
сверху — клики игрока 1 (бирюзовый),
снизу — игрока 2 (розовый).
Яркие штрихи — нажатия, тусклые — отпускания. Рядом показано общее число кликов и длина макроса.
Если файл не распознался
Ошибка означает, что программа не смогла разобрать содержимое ни как GDR2, ни как MessagePack (GDR1), ни как JSON. Обычно это значит:
файл повреждён или обрезан;
это неподдерживаемый формат другого бота (список поддерживаемых ботом ZCB форматов шире, чем у этого инструмента — если у вас файл из другого бота, попробуйте экспортировать/конвертировать его в .gdr2 или JSON через сам бот).
2. Звуки кликов
Есть 4 категории звука:
P1 — нажатие
P1 — отпускание
P2 — нажатие
P2 — отпускание
Вручную: в каждую категорию можно загрузить один или несколько аудиофайлов. Если их несколько — при рендере для каждого клика случайно выбирается один из них (для естественности звучания, как в ZCB).
Импорт клик-пака (.zip): можно загрузить архив в формате ClickpackDB одной кнопкой. Программа сама раскладывает файлы по категориям:
всё, что лежит в папках release/releases → отпускания, остальное (hardclicks, softclicks, microclicks и т.п.) → нажатия;
если внутри пака есть папки player1/player2 (или p1/p2, 1/2) — звуки достаются нужному игроку;
если пак без разделения на игроков — один и тот же набор звуков используется и для P1, и для P2.
После импорта показывается, сколько сэмплов попало в каждую категорию. Кнопка «Очистить все звуки» сбрасывает всё перед загрузкой нового пака.
Если звук не загружен вообще — используется синтезированный клик (короткий тональный щелчок), чтобы результат всё равно можно было прослушать.
3. Настройки рендера
Параметр
Что делает
Громкость P1 / P2
Отдельная громкость для каждого игрока
Общая громкость
Множитель громкости всего трека
Хвост после последнего клика
Сколько секунд тишины добавить в конец файла
Случайный питч
Слегка меняет высоту тона каждого клика в случайных пределах — убирает эффект «одинаковости» при повторе одного сэмпла
Формат файла
MP3 (кодируется через lamejs) или WAV (без потерь, без внешних библиотек)
Если MP3-кодировщик не смог загрузиться (например, нет интернета в момент открытия страницы), рендер автоматически сохранится в WAV с предупреждением об этом.
4. Рендер
Кнопка «Рендерить» запускает сборку: для каждого клика из макроса берётся (или синтезируется) звук, накладывается в нужный момент времени с учётом громкости и питча, всё сводится в один трек через OfflineAudioContext.
После рендера появляется плеер для прослушивания (с движущимся маркером-плейхедом на таймлайне) и кнопка скачивания готового файла.
Технические детали (для интересующихся)
GDR2: реализован по открытой спецификации maxnut/GDReplayFormat (ветка gdr2) — varint-поля, дельта-кодирование кадров, упаковка события в 1 байт (бит0 — продолжение, бит1 — состояние кнопки, оставшиеся биты — дельта кадра). Extension-блоки (доп. данные конкретного бота) корректно пропускаются по указанному размеру, но не разбираются — для рендера звука они не нужны.
GDR1: декодируется как MessagePack, затем прогоняется через тот же гибкий детектор полей, что и JSON (ищет frame/player/down, p1/p2 и похожие имена полей).
JSON: эвристический разбор — ищет массив кадров внутри файла (в т.ч. вложенный, в т.ч. объект-карту по номеру кадра), затем определяет нужные ключи по имени.
Во всех трёх случаях в итоге получается единый список событий «нажатие/отпускание для игрока N в момент времени T», который дальше и озвучивается.
Если попадётся файл, который инструмент не может прочитать, — пришлите его вместе с указанием бота, которым он был записан, разберём точечно.
